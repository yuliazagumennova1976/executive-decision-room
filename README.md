# EXECUTIVE DECISION ROOM

**AI & FINANCE · EXECUTIVE UNIVERSE**  
Интерактивная система структурирования и контроля управленческих решений.

## Реализовано в MVP

- Dashboard: портфель решений, статусы, ближайшие сроки и просроченные действия.
- New Decision: карточка решения со всеми полями ТЗ.
- Decision Analysis: 2–4 альтернативы, редактируемое сравнение, преимущества, недостатки, инвестиции, сроки, финансовые последствия, риски, комментарии и допущения.
- Risk Register: категории, вероятность, влияние, критичность, реагирование, ответственный, статус и матрица 5×5.
- Decision Journal: проблема, альтернативы, допущения, обоснование, утверждающий и дата принятия.
- Execution Tracker: задачи, ответственные, сроки, ожидаемый результат, статусы, комментарии и история изменений.
- Results Review: план/факт, финансовые последствия, причины отклонений, выводы и дата пересмотра.
- Сквозной жизненный цикл: Problem → Analysis → Risk Assessment → Decision → Execution → Review.
- История изменений по ключевым действиям.
- Демо-данные, локальное сохранение, повторное открытие.
- Экспорт подробного Executive Decision Report в PDF.
- Русский и английский интерфейсы с переключателем.

## Технологии

React 18, TypeScript, Vite, Lucide React, jsPDF. Хранение данных — `localStorage` в браузере. Сервер, авторизация, совместная работа и синхронизация между устройствами в MVP не предусмотрены.

## Запуск локально

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Откройте URL, который покажет Vite (обычно http://localhost:5173).

Проверка production-сборки:

```bash
npm run build
npm run preview
```

## Публикация на GitHub + Vercel

1. Создайте пустой репозиторий на GitHub.
2. Распакуйте архив проекта и откройте терминал в папке `executive-decision-room`.
3. Выполните:

```bash
git init
git add .
git commit -m "Initial EXECUTIVE DECISION ROOM MVP"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/executive-decision-room.git
git push -u origin main
```

4. На Vercel выберите **Add New → Project**, импортируйте репозиторий.
5. Framework: Vite (определяется автоматически). Build command: `npm run build`. Output directory: `dist`.
6. Нажмите Deploy.

`vercel.json` уже содержит SPA rewrite.

## Важные ограничения локального режима

- Данные хранятся только в том браузере и профиле, где их создали.
- Очистка данных сайта/браузера может удалить сохранённые решения.
- Данные не синхронизируются между компьютерами и пользователями.
- Для переноса данных на другой компьютер используйте резервное копирование браузерного профиля либо экспортируйте PDF каждого решения. Импорт/экспорт полного JSON-бэкапа можно добавить следующим этапом.
- Не используйте демо-данные как реальные кейсы компаний.

## Структура данных

`Decision` — основная сущность. `Alternative`, `Risk`, `Action` и `Review` имеют собственные ID и `decisionId`, связывающий их с решением. Каждое решение содержит журнал событий `history`.

## Дальнейшее развитие (не входит в этот MVP)

AI-анализ документов, автоматическое извлечение рисков, совместная работа, согласования и электронные подписи, ERP/CRM, уведомления, корпоративные роли и разграничение доступа.


## Первый запуск и демонстрация

При первом открытии приложение загружает четыре условных демонстрационных решения. Любые изменения сохраняются автоматически в `localStorage`. Кнопка «Восстановить демо-данные» предусмотрена в словаре интерфейса, но пока не выведена в UI; для сброса демо-состояния удалите ключ `edr-data` в DevTools → Application → Local Storage и обновите страницу.

Для демонстрации полного сценария:
1. Создайте карточку решения и заполните обязательное название.
2. В Decision Analysis оставьте 2–4 альтернативы и заполните сравнимые параметры.
3. Добавьте риски и оцените вероятность/влияние по шкале 1–5.
4. В карточке решения выберите предпочтительную альтернативу, внесите обоснование и утверждающего.
5. В Execution Tracker добавьте задачи и обновляйте статусы.
6. В Results Review внесите план/факт и управленческие выводы.
7. Сформируйте PDF из карточки решения или раздела Results Review.

## Примечание о PDF

PDF создаётся на стороне браузера библиотекой jsPDF. В MVP текст отчёта формируется на английском/латинице техническим шрифтом jsPDF; для корректного отображения кириллицы в PDF следующим улучшением рекомендуется встроить Unicode TTF-шрифт (например, Noto Sans) в проект. Сам интерфейс полностью двуязычный.
